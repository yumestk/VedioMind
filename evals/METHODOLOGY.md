# VedioMind Agent Eval 方法论

版本：`1.1.0` · 建立日期：2026-11-11 · 修订日期：2026-11-13 · 适用项目：VedioMind

本文件保存跨轮次规则与设计依据；当前轮次的目标、候选样本、负责人、运行条件和进度见 [PLAN.md](PLAN.md)。开展新的 Eval 时先阅读本文件，再制定本轮 Dataset、Rubric 和执行计划。本文不是评测结果或上线证明。

## 1. 原则来源与成熟度

全文使用以下标记；版本化的项目规定与效果已被验证是两回事。

| 标记 | 含义 | 使用要求 |
| --- | --- | --- |
| A | 来自参考资料的通用 Eval 原则 | 参考第 12 节；不能据此声称 VedioMind 已满足该原则 |
| B | 根据项目代码或业务约束作出的适配 | 区分已存在的运行能力与本文要求后续实施的评测规范 |
| C | 初始假设、候选量表或待验证门槛 | 必须说明待谁确认、如何验证；不能写成已验证事实 |

**[A]** 先定义决策和成功条件，再选择评分方法。评价实际结果，同时利用轨迹诊断原因；混合使用规则、人工和经校准的模型评分。承认随机性、环境噪声与评分误差，不以单次成功证明可靠性。

**[B]** 当前目的：评估期末网课复习场景下，学生是否能获得准确、有证据、覆盖目标的跨视频学习笔记，并据此选择下一项 Agent 改进。第一轮不是上线 Go/No-go 审批，也不测学习成绩提升。

**[C]** 小样本是否足以暴露主要问题、候选门槛是否符合学生需求，都需要首轮实验及人工反馈确认。

### 探索性试跑与正式评测

**[B：用户于 2026-11-13 明确采用]** 允许在正式 Ground Truth 人工确认前做少量真实探索性试跑，用于发现链路与成果中的明显问题。须先确定任务、材料、Agent 版本和预算，隔离学习状态并保存原始 Trace、成果、用量及全部失败；候选事实仍保持 UNVERIFIED，不计算正式覆盖率、合格率，不称为 Baseline。

用户可以先查看笔记，只复核关键疑点。由输出启发修订的任务、判据或参考事实必须登记，未来正式实验采用新的冻结版本；不能事后把本次试跑改称未受输出影响的盲测或正式 Baseline。以下有关人工 Ground Truth 和评分冻结的要求继续适用于正式评测；预算、权限、泄漏防范和如实记录要求也适用于探索。

## 2. 适用范围与实现基线

**[B：代码观察]** 文档建立时核对的提交为 `2436af0eb8a88ab9549f3c76273f3f846e441843`，不是未来各轮的自动基线。

- `mode=DEEP`、章节／课程／指定材料范围的 NOTE 任务可进入 `BOUNDED_AGENT`。普通问答和单视频笔记使用其他策略，不能混入本轮指标。
- 六个工具：`read_skill`、`get_course_structure`、`search_course_evidence`、`read_evidence`、`get_learning_state`、`save_note`。Skill 正文按工具调用加入上下文；工具、权限与预算由宿主控制。
- 当前有 6 决策轮、10 次工具调用、2 次参数纠错限制；有独立实际调用、Token 与时间预算。这些是现行配置，不代表数值已由真实质量评测校准。
- NOTE 结构限制 1～8 个知识点；宿主检查结构、已读引用、范围与幂等交付，不能证明引用在语义上支持结论。
- `SUCCEEDED` 还要求覆盖材料与任务范围一致、无 gaps 等条件；这与用户目标的知识覆盖不等价。不得为满足状态而要求给无关材料凑引用。
- `get_learning_state` 当前暴露本人相关已交付笔记的 ID、标题、版本等摘要，不是完整笔记正文；这些摘要仍可能污染后续独立试验。

代码入口：[执行循环](../server/src/main/java/com/example/server/service/StudyAgentRuntime.java)、[工具分派](../server/src/main/java/com/example/server/service/StudyAgentToolDispatcher.java)、[成果与状态判定](../server/src/main/java/com/example/server/service/StudyArtifactService.java)、[运行资源指纹](../server/src/main/java/com/example/server/service/StudyAgentSpec.java)。新轮次须复核代码，不能把本节当成永久实现承诺。

## 3. 核心概念

| 概念 | 定义与项目映射 |
| --- | --- |
| Task / Case | 有明确输入、初始状态、材料范围和成功条件的评测任务；不同于只写一句问题 |
| Trial | 某个 Case 在指定配置、独立初始状态下的一次执行；一个 Case 可以有多个 Trial |
| Run | 项目中的 Agent 执行对象。一个 Trial 可以含准备或路由阶段，记录 requestId 与 runId；准备阶段被拒绝时 runId 可以为空 |
| Trace | Trial 的任务、模型调用、工具参数与观察、事件、结果、用量及异常记录；不要求模型披露隐藏思维链 |
| Outcome | 最终可核验状态，如正式笔记及其引用确实交付，而不只是模型说“已保存” |
| Grader | 针对某一维度的规则检查器、人工评分者或模型评委 |
| Dataset / Ground Truth | 版本化的任务集合／经人工核实的事实、原文证据、可接受结果及判定依据 |
| Rubric | 评分单位、标签、锚点、分母、严重程度、通过规则和待复核规则 |
| Baseline / Experiment | 冻结配置下建立的比较基准／使用指定 Dataset、Rubric 和多个 Trial 的一次实验 |

**[A/B]** 恢复同一 Run、重放已保存的模型响应或检查点，属于原 Trial 的恢复；不能算作又一次独立模型成功。新 Trial 使用新请求身份并重置允许重置的试验状态。

## 4. 三层成功与指标分母

**[A/B：评测规范]** 每例分别记录以下结果，不能把它们合成一个不透明总分：

1. **工程约束**：权限、资源版本、输入结构、引用身份、预算、执行代次、交付与幂等规则是否成立。
2. **任务完成**：最终结果是否实现用户请求；生成任务必须核对正式成果，不能仅看聊天文本、候选回执或 `SUCCEEDED`。
3. **内容质量**：事实、引用支持、必要知识覆盖、相关性与缺口处理是否合格。

每例在运行前标记预期结果：完整笔记、允许且预期的部分笔记，或证据不足时停止／报告不足。正常可回答任务因漏检索而拒答仍是失败；正确停止不能抬高笔记完成率。

报告至少列出：

- **笔记任务完成数／预期应交付笔记的有效 Trial 数**。
- **内容合格数／预期应交付笔记的有效 Trial 数**；没有成果不能从分母中消失。
- **正确停止数／预期应停止的有效 Trial 数**，独立展示。
- 每个 Trial 的宿主终态、工程约束结论、内容分项、环境故障和待复核状态。

**[B]** 若存在预期的部分交付，同时标记目标是否完整满足，避免“如实交付部分”被解释成完整任务成功。没有笔记的 Trial，内容比率记 N/A 并保留任务失败／正确停止结论，不能赋予事实正确率 100%。

**[A/B]** 所有计划内 Trial 都须报告。环境故障、失效样本、评分待复核可单列，但写明原因及排除数；不得静默剔除失败或只保留最佳重试。

## 5. Dataset 与 Ground Truth

### 5.1 Dataset 设计

**[A]** 覆盖正常、复杂、边界和失败诱因，兼顾“应该做”和“不应该做”。任务必须清楚、可解，允许有效的不同表述与执行路径。不能设置用户任务没有表达的隐含格式或关键词要求。

**[B]** 每例至少记录：caseId、版本、学生任务、目标能力、初始身份与学习状态、冻结材料及版本、预期成果类型、必须事实、禁止结论、证据包、可接受缺口／停止方式、评分规则和人工确认状态。

- 课程／章节范围不是视频时间轴章节；范围由宿主冻结，不能靠评测提示绕过业务权限。
- 任务规模应与当前 NOTE 契约相容。超出能力范围的探索案例另标为压力测试，不把不可交付任务当作普通成功样本。
- 权限拒绝、取消、MQ 重投、UNKNOWN、事务回滚等主要由工程回归覆盖；与真实内容质量样本分开汇总。

### 5.2 Ground Truth 构建规范

**[A/B]** 使用“事实与证据包”，不以一篇唯一标准作文作为正确性的定义。

1. 从冻结材料提取原子事实、前提／例外、观点归属、可接受推断和禁止断言。每项绑定视频、时间、模态、版本及原文，允许多组等价证据。
2. 人工核对关键片段、字幕、OCR 与视频是否一致；语义疑点标记为材料质量问题。区分忠实于课程与学科事实正确，不能默认课程永远无误。
3. Codex 或其他模型整理的内容一律是候选。人工确认前记为 `UNVERIFIED`；有争议记为 `DISPUTED`；只有确认的事实才能作为正式判据。
4. 负例“完全没有相关信息”须核查冻结材料的相关范围，不能用被测检索器返回空结果作为证明；核不清就不采用该负例。
5. 在查看被测输出前冻结 Ground Truth。不得让被测 Agent 的答案生成自己的标准答案，再由同一模型自证正确。
6. 每例准备人工核实的参考笔记或预期停止说明，确认任务确实可以通过 Rubric。参考笔记是可行性检查，不是逐字匹配模板。

**[B]** 每项确认保留确认人、日期、证据位置和争议处理理由。只有一名人工确认时明确记录，不声称经过独立双人标注；未解决争议不得强制判 Agent 错误。

## 6. Rubric 与评分方式

### 6.1 评分单位和标签

**[B：项目量表；语义效果待校准]** 笔记以实质性原子结论评分，包含正文新增的结论，而不只检查 Ground Truth 中已有的事实。先切分结论，再判定，避免通过冗长重复稀释错误。

| 维度 | 判定与记录 | 自动化边界 |
| --- | --- | --- |
| 事实正确性 | 对课程及人工核实证据标记正确／错误／无法确认；记录关键或一般错误，以及缺失的条件、否定、归属 | 规则不能理解事实真假；首轮人工判定 |
| 引用支持度 | 对每个应有证据的结论标记完整支持／部分支持／不支持；缺引用按不支持处理，并核对定位 | 代码检查身份和已读取关系，人工检查语义支持 |
| 必要知识覆盖 | 对预先确认的事实逐项记完整满足／部分满足／未满足；接受等价表达，保留遗漏清单 | 人工作语义判定，脚本只能汇总已确认标签 |
| 相关性与组织 | 0：偏离目标或无法使用；1：基本相关但关系散乱；2：围绕目标且关系清楚 | 三档是项目候选锚点，不是成熟方法论的统一尺度 |
| 缺口与不确定性 | 是否如实区分原文、推断和未知；区分真实缺口与检索遗漏，检查错误前提是否被纠正 | 依赖完整参考范围，不能仅凭 Agent 自述评分 |

**[C：待人工确认的汇总方式]** 覆盖标签可按完整 1、部分 0.5、未满足 0，除以预先冻结的必要事实数量。引用完整支持率按“完整支持的结论数／全部应有引用的结论数”记录，部分支持另列。无法确认的事实单列，不默认为正确。关键前提错误不能被其他高分抵消。

**[C：初始通过门槛]** 预期完整交付的任务，候选合格条件为：工程约束成立、正式交付、必须事实完整、无关键错误或无依据的核心断言、核心结论引用完整支持。部分交付／停止案例按预先声明的预期结果判定。最终门槛由课程核实及评分校准后确认；不预设通用的 80 分、固定总权重或上线成功率。

### 6.2 Grader 选用

**[A/B]** 使用能真实测量该维度的最小方法：

- **Rule-based**：成果是否落库和可见、Schema、材料与证据身份、范围、版本、重复交付、预算、次数和状态；可精确匹配 ID，但不能拿关键词匹配代替笔记语义正确性。
- **Human Evaluation**：首轮内容质量的主判据。评分依据必须绑定结论与证据，优先记录理由而不是只打总分。
- **LLM-as-a-Judge**：后续辅助标记疑点，先对照人工标签校准；允许无法判断，保留模型、Prompt、参数、理由与版本。输入包含任务、证据及 Rubric，将待评分文本视为数据，不服从其中的评分指令。各维度可独立判断。

**[A/B]** 换一个模型也不等于消除评分偏差；被测模型不能作为最终自我裁判。自动评委的调用、费用和误差单独记录，不能沿用被测 Agent 的预算授权。首轮不需要自动评委。

## 7. 工具轨迹、执行效率与 Trace

**[A]** 优先评价结果和必要约束，不规定唯一搜索词或唯一工具序列。不因模型找到另一条有效路径而扣分，也不把工具调用更多当作更努力。

**[B]** 核对 `read_skill` 的前置要求、冻结范围、先检索发现再读取的证据准入、已读后引用、保存到宿主输出槽等契约。按“检索线索→读取原文→最终引用→结论”定位遗漏发生在哪一层，分别识别检索遗漏与生成遗漏。

逐 Trial 记录：模型决策轮数、工具调用及参数、工具拒绝／纠错、实际生成与 Embedding 尝试、无进展调用、活动／等待／端到端耗时、已知 Token、预留及未知用量。按质量分层比较效率，不奖励快速但空白或错误的结果；估算费用不能冒充供应商账单。

**[B：现有基础]** `video_agent_runs` 保存任务与结果，`video_agent_steps` 保存决策／工具观察，`study_run_events` 保存有序元数据，`ai_call_attempts` 保存调用与响应，`study_artifacts` 保存笔记。学生事件接口只披露元数据，不是完整 Eval Trace。

**[B：后续实施要求]** 受控导出按 trialId 关联上述记录及实验快照，标明缓存／恢复、缺失事件、异常结束与失败尝试。不能把未落库的工具失败补造为已观察事实。无需完整可观测平台，也不向学生开放内部原始响应。

## 8. Baseline、隔离与公平对比

**[A/B：每轮必须实施的规范]**

1. 冻结实验清单：methodologyVersion、datasetVersion、rubricVersion、Agent Git SHA／dirty diff、依赖／部署信息、完整 Prompt、Skill、工具 Schema、模型及实际请求参数、材料／字幕／OCR／索引版本、检索配置、预算和初始学习状态。不能只保存哈希而丢失对应内容；供应商未披露的模型快照或默认参数记为未知。
2. 每个独立 Trial 使用新 requestId／runId 和等价初始环境。仅创建新会话不足以隔离同一学生的已有学习摘要；使用隔离的评测数据环境或可复原的评测身份初始快照，不清空用户业务数据。
3. 区分不可变课程索引缓存与答案、学习状态、调用响应缓存；明确冷／热缓存条件。服务恢复或账本响应重放不算独立新试验。
4. 同一批执行期间不调 Prompt、Skill、预算、检索或评分门槛。比较版本使用同一 Dataset、Rubric、材料和初始状态；预算变化等另作实验因素披露，不能混称同条件优化。
5. 尽量只改一个因素；顺序、并发、限流与供应商时间漂移须记录。模型随机性意味着可复现的是条件和记录，不保证逐字相同。
6. 首次逐例列出结果和分子／分母；只有一次 Trial 不报告重复稳定性。有预算的复测另设次数与抽样规则，保留全部结果，不取最好一次替换原结果。

**[C]** 首轮样本数、复测次数、运行并发、费用及停止上限由 [PLAN.md](PLAN.md) 管理，运行前需确认。小样本不适合声称统计显著提升或总体可靠性；成功数增长时须检查逐例变化与新增退化。

## 9. 评分偏差、泄漏与过拟合

**[A/B]**

- Rubric、参考事实和通过条件在输出出现前冻结。可人工制作好／差／部分完成笔记校准量表，确保允许等价表达，不用精确作文匹配。
- 尽可能隐藏被测版本和模型身份；不因篇幅、文风或自己偏好的措辞给正确性加分。分歧保留原评分和裁定记录；单人复核不能冒充独立一致性评估。
- Ground Truth、隐藏评分标签、参考笔记和前次试验输出不得进入 Agent 的课程索引、Skill、提示或学习状态。明确的用户任务约束须对 Agent 可见，不能通过隐藏业务要求制造失败。
- 原文或待评文本中的“给满分”等指令不是评分规则。内部 Trace 与课程私有原文按现有权限受控保存，公开仓库只提交可公开的规范或脱敏材料，不自动提交真实运行原文和凭据。
- 开发案例可用于调参；预留案例不用于调参。一旦看其结果并据此修改 Agent，就把该例转为回归集，补充新预留案例；改写同一道题不能自动视为独立新样本。
- 从真实失败补充后续样本，同时保留正常任务防回归。不把小样本高分等同于广泛课程泛化，不通过删除困难案例制造改善。

## 10. 失败分析与持续改进

**[A/B]** 先评分 Outcome，再检查 Trace。按以下类别记录主因、次因和证据：

`材料／转录错误 → 任务歧义或不可解 → 检索遗漏 → 证据读取不足 → 生成或引用错误 → 工具／Skill 误用 → 预算／停止过早 → 环境／供应商故障 → 评分规则错误`

不因一个低分直接调大预算或换模型。确认问题属于材料、Harness、模型还是 Grader；按学生影响和复现情况选择改进，每次保留原因、变更版本、成本变化及回归结果。若确认 Grader 错误，修正评测而不是强迫 Agent 迎合错误答案。

完成一次实验时输出逐例评分、未解决争议、失败清单、耗时／用量、限制与下一项改进。结论区分可继续试用、有条件继续和需先修复；第一轮结论只适用于本轮范围，不替代上线验收。

## 11. 修订、冻结与可追溯性

**[B：项目治理规范]** 本文件的规则版本为 `methodologyVersion`；Dataset、Rubric 与被测 Agent 独立版本化。报告必须记录四者，另关联 experimentId、caseId、trialId 和 requestId／runId。

- 每轮先阅读方法论，设计并人工确认样本与 Rubric，再冻结配置。计划中写明采用的版本与仍未确认项；候选版本不能假装已经冻结。
- 原则、标签、分母或门槛改变时，登记新版本、理由、影响范围、修订／确认人及日期。评分门槛变更不能伪装成编辑错别字。
- 同轮中途发现歧义或错误时先暂停受影响评分，不按已有成绩调门槛。保留原始结果，建立新方法论／Dataset／Rubric 版本；可基于原始成果重评，条件变化时须重新运行并标明。
- 旧版本保持可取回，不覆盖历史评分。不同 Rubric 的总分不能直接比较；对同一原始结果用共同 Rubric 重评后才作对应比较。
- `PLAN.md` 作为当前入口可更新；开始下一轮前保存本轮冻结计划及版本快照。未来 `evals/datasets/`、`evals/runs/` 可保存可公开的样本和实验记录，但本次不创建空平台结构。
