# ADR-0029：由宿主执行有界原文补读

- 状态：Accepted
- 日期：2026-11-26
- 适用：`bounded-study-v11` 跨视频笔记 Runtime，B1-B 实验候选

## 背景

`bounded-study-v10` 可以拒绝未读引用，但搜索线索仍可能在第一次 `READ` 后留在已读集合之外。006 N02 曾选中第 14 讲的锚点，窗口因容量延后。007 N02 发现了该讲的线索，第一次读取时只选了第 16 讲。两次都直接转入 `FINALIZE`。007 首存因未读引用被拒，修正后交付了仅依据第 16 讲的部分笔记。

B1-A 最初计划在收尾前给模型一次小额度决策，由模型从宿主筛出的候选中选择读取或跳过。候选最终收敛到一个，高置信度的来源缺口已由宿主判断。B1-A 保留了模型的事前跳过权，同时消耗一次模型决策、一次生成调用和一个工具槽。四组离线回放中，三个有候选的样本改由宿主读取后，至首次保存的累计预留少了 32,732–33,969 个估算单位，并保留了原决策槽。按相同的修正输入增长情景，两种补读方案都无法事前同时预留首存和一次修正。

## 决策

采用 B1-B。宿主在首次成功读取后、Runtime 因探索预算的软门槛即将进入 `FINALIZE` 时，最多执行一次本地补读。候选必须处于当前任务的授权范围和冻结版本内，已在本 Run 被检索发现但尚未读取。区分已选但因容量延后的 `DEFERRED_CAPACITY` 和发现后从未选中的 `UNSELECTED`。首版只为用户明确要求、尚无已读证据且线索与任务有明确主题重合的材料补读，最多选一个锚点。

- 补读计一个工具等价槽，沿用现有读窗、容量检查、账本和任务硬预算。读取使用 2 秒数据库事务超时，保留权限、来源版本、执行代次检查。至少预留一次完整保存才可将补读原文装包。允许事前修正预留为零，首存后的修正机会按实际结算、请求容量及剩余槽动态判断。
- 由独立 `HOST_SUPPLEMENT` Checkpoint 记录领取、来源版本、窗口摘要、所获原文和装包结果。已提交的结果在恢复时复用；已领取但无结果的读取记录为中断，保留该槽消耗并进入收尾。模型请求继续由 `AGENT_BUDGET` 和原账本保证同一检查点下的请求指纹一致。
- 已获准原文以带宿主来源标记的文本数据消息加入下一轮，既有原生工具调用与观察保持配对。只有实际进入该轮请求的原文才加入决策前可引用快照。模型仍负责判断语义支持、选取引用及声明缺口，宿主按原事务路径验收和交付。

## 验证与后果

- 四组冻结 Trace 的实现级回放中，006 N01、006 N02、007 N02 均装入了新增原文，006 N03 因无足够的补读理由而跳过。隔离 MySQL 共 83 项通过，覆盖真实锁等待超时、读取许可恢复及首存拒绝后按账本开放修正。
- 008 对 N02 实测一次。第 3 轮与 007 取得相同的 29 条第 16 讲原文，宿主补读后取得 15 条第 14 讲原文，全部装入第 4 轮请求，最终引用其中 10 条。字幕直接支持 LIFO 和 FIFO，补上了 007 的来源缺口。供应商接受该请求，首存通过并交付 `SUCCEEDED`；007 第 5 轮交付 `PARTIAL`。本次读窗链路耗时 139 ms，首存增加 6,582 个输入估算单位。
- 宿主失去了模型的事前跳过判断，相关锚点的完整窗口也可能带入无关邻段。即使首存预留充足，首次保存失败后仍可能没有可用的修正预算。008 未触发实际修正。搜索词、缓存命中及供应商时延同时变化，单次结果只证明这一执行路径在该例走通，语义判断仍待人工复核。
